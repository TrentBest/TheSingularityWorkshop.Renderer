# Gallery recipe: Event Horizons

## What this exhibit means

The SVG is generated by a sample that constructs five `RendererComputationMachine` instances, advances them through FSM_API, and reads their resulting `CurrentRepresentation` values. The visual glow, pulse, and movement are SVG presentation.

## Reproduce it

From the Renderer repository root:

```bash
dotnet run --project samples/LivingRenderer/LivingRenderer.csproj --configuration Release -- docs/assets/living-event-horizons.svg
```

The generated result is [living-event-horizons.svg](../assets/living-event-horizons.svg). The source sample is the authority for how the state values are produced.

## What it proves

- Representation states can be driven through the FSM-backed sample path.
- The result can be made visible in a compact SVG snapshot.

## What it does not prove

This is not live telemetry, a running simulation, an observer-driven policy benchmark, or a frame-time measurement. SVG animation does not mean the FSM is continuing to tick after generation.

## Next recipe

Make the observer and policy inputs controllable, rerun the actual policy/frame path, and regenerate the image from resulting representation counts. Keep recorded timings separate from animation and record the exact input beside each snapshot.
